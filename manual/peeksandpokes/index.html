Peeking and a Poking

With 8-bit programming, one of the most common tasks we face is how to set specific values in memory. Even in basic we find ourselves needing to set a flag, update a color value or turn some feature on or off that just isn't reachable using the languages dialect. This is where we need to peek and poke.

Lets look at a fun and simple example using the cursor and the rate that it flashes. If we look at the reference manuals for the Foenix we can see that the cursor blink rate is a set of flags inside of a memory address at $D010. We can look at what value is in there by default by typing:

print peek ($D010)
5

The peek command will return the one-byte value of the value stored in memory address $D010. In this case its 5. If we look at the memory information from the Foenix reference manual we can see each of the 8 bits has something to do with the cursor.

Address Bit 7 Bit 6 Bit 5 Bit 4 Bit 3 Bit 2-1 Bit 0
$D010 Flash On/Off Flash Rate Enable

We can change one-byte values in memory using the poke command. Let's see if we can change the cursor behaviours using the table. So when we asked what the byte was set to the system essentially told us the value 5. In binary that would be 00000101. So The flash rate bits are set to 1 and 0 (4) and the bit 0 value is turned on (1) for a total of 5. This means if we set bits 2 and 1 to 0 then we should flash the slowest we possible could. Lets try poking that value:

poke $D010, 1

You should now see the cursor flash every 1 second. Lets turn the flashing off just for fun (we can always reset the unit to go back to default).

poke $D010, 9

Now the cursor won't flash at all and should be stuck on the on position. This is the because we set the value of 8 (bit 3) + enable (bit 1) = 9 (00001001).

But what about bigger numbers?

So this is all cool poking and peeking one byte numbers and all, but what about when we need to do something larger? Well fortunately for us in SuperBasic we have a few extra commands that help out alot with this.

Command Bytes Max Value
peek / poke 1 255 ($FF)
peekw / pokew 2 65535 ($FFFF)
peekl / pokel 3 16777215 ($FFFFFF)
peekd / poked 4 Ridiculously Large Number ($FFFFFF)

You might ask why we'd need all these? Especially the larger ones. Well it turns out that 3 and 4 byte numbers are used in colors frequently. For instance, the Foenix keeps its colors in look up tables (or LUTs for short). Each color is assigned a number or index and is comprised of 3 bytes the same as you are probably used to if you ever do any web development. For instance the hex code #641e16 is a dark red. It's made up of three bytes each one representing a value between 0 and 255. The first byte is the amount of red, the second is the amount of blue and the third is the amount of green. When all three are put together it represents a number between 0 and 16777215.

Lets do something with that color to demonstrate the point. Enter the following into the basic prompt:

poke 1,0
pokel $D848, $641E16

What happened? If you machine behaved like mine, it changed the background to a dark rich red represented by the hex code. This code by the way was just an arbitrary one I picked from htmlcolorcodes.com, but it demontrates why we need pokel as a command. Reset your machine and try this one:

poke 1,0
poke $D848, $641E16

Notice it isn't the same color. Thats because the POKE only really changed to the value $16 at the end of that hex code. If you were to use a pokew only the $1E16 would work.

So color when it comes to bitmaps and sprites have one more byte attached to them (though at time of writing I'm not sure its used). It's an alpha value. So the format in hex would be RRGGBBAA where A is the alpha value between 0 and 255. This would require a peekd to set.

Indirection Operators

The commands peek and peekw have a really cool indirection operator shortcut for them as well and it can be confusing if you are coming from other versions of Basic.

In Commodore 64 basic the ? is used as a shortcut for print. So the command:

? "Hi"

would print hi to the screen. If you tried that on your SuperBasic prompt on the Foenix you'll get the dreaded Type mismatch error.

In our world the ? is an indrection operator for both peek and poke. It can be either depending on how it's used. For instance, in the previous examples were we always setting the MMU page to a value before we started poking on things like this:

poke 1,0
print peek(1)

This will set memory address $0001 to 0 and then print what we set it to. The same commands using the indirection operator would be:

?1 = 0
print ?1

When we use the indirection on the left side of the equals is means set memory address $0001 to 1. Later when we ask it to print ?1 it will do the same thing as printing the peek of memory address $0001.

If we use this on our previous cursor example we could go like:

?$D010=1

To make the cursor flash slow or

?$D010=9

To freeze it.

Likewise we do have an indirection operator for two byte values as well and its the !. If we needed to set two bytes in memory and then retrieve it we could just do something like:

!$2000=$FFFF
print !$2000

Notice the value is 65535, this is the max two bytes can be.

At the time of writing there is no indirections for 3 or 4 byte values which is a shame but using poke and peek is pretty common in code. The indirection, while cool, isn't really as readible as it's counterparts.

Fun Example

This fun example shows a fun way to use pokel. Don't worry too much about the event command, we'll cover it later, just know that this is going to make something happen every 1 second (or 70 frames).

10 event1=0
20 poke 1,0
30 repeat
40 if event(event1, 70)
50 r=random(255):g=random(255):b=random(255)
60 v=r*b*g
70 pokel $D848, v
80 print str$(v)+" ";
90 endif
100 until false

If this runs correctly you should see your text screen change color every second and the 3 byte value it was set to be printed onto the screen.
